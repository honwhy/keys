# KeyTune 功能拆解总览

> **KeyTune · 键音 —— Play by Keys**
>
> KeyTune 是一款专为手机横屏设计的轻量音乐小游戏。玩家根据屏幕提示，在 15 键虚拟钢琴上按下对应琴键，跟随旋律完成演奏；系统用 PERFECT / GREAT / GOOD / MISS 判定每次按键，以 Combo、得分和评级给出即时反馈。你既可以跟着曲目挑战节奏，也可以自由弹奏、识别和弦，还能把整段演奏记录成可回放的作品。它不追求真实钢琴模拟，而是用「看得懂的音符 + 按得爽的琴键 + 停不下来的连击」，让任何人在 3 秒内上手、30 秒内完成第一段旋律。

本目录是 `docs/requirement.md` 的落地拆解：先搭框架，再按依赖顺序逐个实现。每个 Feature 都是可独立验收的交付单元，包含业务流程、功能设计、性能要求、验收标准，以及该 Feature 新增/复用的图片与音频素材规格。

> MVP 素材以 `../design-requirements.md` 为准：9 张图（3 张打底 + 6 张封面）+ 7 个短音效，音符实时合成。各 Feature 只列本 Feature 新增/复用的素材；键帽、音符、判定、UI、分享卡全部用代码绘制。

---

## 1. 拆解原则

1. **先有壳，再有键；先有键，再有游戏。** 框架 Feature 不追求视觉效果完整，但必须让后续 Feature 有稳定的页面、导航、存档与设置入口。
2. **每个 Feature 可单独演示。** 完成一个 Feature 就能看到、听到、操作到明确变化。
3. **规则先行。** 判定、计分、评级属于核心规则，先于具体玩法实现，避免两套模式各算一套。
4. **内容与玩法分离。** 曲库先建立内容模型，再让跟弹、节奏挑战、闯关复用。
5. **素材随 Feature 交付。** 每个 Feature 文档内列出素材编号、尺寸、格式、响度；未列出的素材默认复用已有资产。
6. **不引入技术选型。** 文档只描述玩家可感知的行为、界面与指标，不规定框架、语言、部署。

## 3. 全局素材约定

### 3.1 视觉基准

| 项目 | 约定 |
| --- | --- |
| 逻辑画布 | 1920×1080 横屏 |
| 导出 | 位图统一 @2x（标注尺寸 ×2） |
| 安全区 | 左右 96px、上下 48px |
| 主色 | 青 `#35E0D0`；强调珊瑚 `#FF6B6B`；金色 `#FFC857` |
| 背景 | `#0B0E17`；面板 `#171B2B` |
| 字体 | 系统黑体；数字用几何无衬线 |
| 图片文字 | 不烘焙文字（Logo 除外） |
| 图标 | 优先 SVG；位图图标 @2x PNG |

### 3.2 音频基准

| 类型 | 规格 |
| --- | --- |
| 短音效 | WAV / 44.1kHz / 16bit / 单声道 / 40～1500ms / -14 LUFS / 峰值 ≤-3dBFS |
| BGM / 伴奏 | 不做 |
| 音符 | 15 个音符实时合成，0 个音频文件 |
| 命名 | `sfx_<场景>_<名称>_v1.wav` |

### 3.3 素材编号规则

- 图片：`M-IMG-01` ～ `M-IMG-09`，共 9 张。
- 音频：`M-SFX-01` ～ `M-SFX-07`，共 7 个。
- 全项目只有这一套素材，不再按 Feature 拆独立编号。

### 3.4 共用素材

| 编号 | 素材 | 用途 |
| --- | --- | --- |
| M-IMG-01 ～ M-IMG-03 | 应用图标、Logo、通用背景 | 启动、首页、游戏、设置 |
| M-IMG-04 ～ M-IMG-09 | 6 张曲目封面 | 曲库、结算、每日挑战 |
| M-SFX-01 ～ M-SFX-07 | 7 个短音效 | UI、判定、Combo、结算 |

> 尺寸、格式、响度与描述要求统一见 [`design-requirements.md`](../design-requirements.md)。

## 5. 完成定义（Definition of Done）

一个 Feature 视为完成，必须同时满足：

- 本文档列出的功能点全部可用，无占位按钮。
- 验收标准逐条通过，或有明确豁免记录。
- 性能指标在目标机型达标，无明显卡顿、爆音、丢音。
- 新增素材齐备，尺寸/格式/响度符合规范，且已接入。
- 不影响已完成 Feature 的既有行为。
- 更新本目录清单与 `docs/requirement.md` 的映射状态。
