# F07 · 结算、评级与成绩记录

> **KeyTune · 键音 —— Play by Keys**
>
> KeyTune 是一款专为手机横屏设计的轻量音乐小游戏。玩家根据屏幕提示，在 15 键虚拟钢琴上按下对应琴键，跟随旋律完成演奏；系统用 PERFECT / GREAT / GOOD / MISS 判定每次按键，以 Combo、得分和评级给出即时反馈。你既可以跟着曲目挑战节奏，也可以自由弹奏、识别和弦，还能把整段演奏记录成可回放的作品。它不追求真实钢琴模拟，而是用「看得懂的音符 + 按得爽的琴键 + 停不下来的连击」，让任何人在 3 秒内上手、30 秒内完成第一段旋律。

| 项目 | 内容 |

### 1.1 本 Feature 包含

- 结算页布局与动画节奏。
- 评级 S/A/B/C/D 的展示与解锁条件反馈。
- 分数、准确率、最大 Combo、四类判定数量、用时。
- 新纪录判定与提示。
- 最佳成绩的保存与读取（按曲目 × 模式）。
- 再来一次、下一首、返回首页。
- 从结算保存演奏记录（交给 F10）。
- 分享入口占位（F12 实现）。

### 1.2 本 Feature 不包含

- 判定、Combo、分数、评级的计算（F04）。
- 曲目列表与详情（F03）。
- 分享卡片生成（F12）。
- 闯关星级与章节奖励（F08）。

## 3. 业务流程

### 3.1 进入结算

```text
游戏结束（F05/F06）
  ↓
冻结画面 300ms
  ↓
结算页淡入
  ↓
播放评级揭示动画（可点击跳过）
  ↓
分数滚动 → 统计逐项出现
  ↓
判断新纪录 / 新评级 / 成就（F11）
  ↓
显示操作按钮
```

### 3.2 评级揭示

```text
背景压暗 + 光效聚集
  ↓
评级字母从大到小落定（S 金色 / A 青 / B 蓝 / C 灰 / D 珊瑚）
  ↓
播放对应评级音效
  ↓
显示“新纪录”或“最佳评级”标识（如适用）
  ↓
分数从 0 滚动到最终值（800ms）
  ↓
统计项依次淡入（每项 80ms）
```

- 任意点击/触摸可跳过动画，直接显示最终状态。
- 跳过动画不跳过音效（可静音）。
- 减少动效时，取消光效与翻转，直接淡入。

### 3.3 操作流

```text
结算页
  ├── 再来一次 → 同一曲目、同一模式、同设置 → 3-2-1
  ├── 下一首 → 曲库顺序的下一首已解锁曲目 → 曲目详情
  ├── 保存演奏 → 输入标题 → 保存成功 Toast（F10）
  ├── 分享 → 分享预览（F12 前显示“即将开放”）
  └── 返回首页 → 首页
```

### 3.4 保存成绩

```text
结算数据
  ↓
读取该曲目 × 该模式的历史最佳
  ↓
逐项比较：分数、评级、准确率、最大 Combo
  ↓
分别更新更高的项
  ↓
写入本地档案
  ↓
若分数创新高 → 标记“新纪录”
```

## 4. 功能设计

### 4.1 结算页布局

以 1920×1080 为例：

```text
┌──────────────────────────────────────────────────────────┐
│                                                          │
│   ┌──────────────────────────────────────────────────┐   │
│   │  小星星 · 节奏挑战                    [新纪录]   │   │
│   │                                                  │   │
│   │        ╭──────╮                                  │   │
│   │        │  S   │        得分                      │   │
│   │        ╰──────╯        12,340                    │   │
│   │        评级                                      │   │
│   │                                                  │   │
│   │   准确率 96.2%   最大 Combo 32   用时 00:32      │   │
│   │   PERFECT 38   GREAT 3   GOOD 1   MISS 0         │   │
│   │                                                  │   │
│   │   [保存演奏]  [分享]                             │   │
│   │                                                  │   │
│   │   [再来一次]      [下一首]      [返回首页]        │   │
│   └──────────────────────────────────────────────────┘   │
│                                                          │
└──────────────────────────────────────────────────────────┘
```

- 结算面板 1400×900，居中，背景压暗 70%。
- 评级位于左侧视觉中心，分数位于右侧，统计在下方。
- 主操作“再来一次”最大、最亮；“下一首”次之；“返回首页”最弱。
- “保存演奏”与“分享”为次级操作，位于统计下方。
- 窄屏（1280×720）时，面板缩放至 95%，统计改为两列。

### 4.2 评级展示

| 评级 | 颜色 | 光效 | 文案 |
| --- | --- | --- | --- |
| S | 金色 `#FFC857` | 旋转光芒 + 粒子 | “完美演奏！” |
| A | 青色 `#35E0D0` | 柔和光晕 | “非常棒！” |
| B | 蓝色 `#5B8CFF` | 轻光晕 | “不错！” |
| C | 灰色 `#8A93B2` | 无 | “再练一次会更好” |
| D | 珊瑚 `#FF5A6E` | 无 | “慢慢来，先熟悉按键” |

- 评级字母使用大字号（160～200px），带描边，保证在光效上可读。
- 不展示“失败”“不及格”等词。
- S 评级额外显示“MISS ≤1、准确率 ≥98%”的达成说明（可选小字）。
- 跟弹模式无分数时，评级区域下方显示“首按准确率”。

### 4.3 统计项

| 统计 | 说明 | 格式 |
| --- | --- | --- |
| 得分 | 节奏挑战显示；跟弹显示“—” | 千分位 |
| 准确率 | 加权准确率 | 百分比 1 位小数 |
| 最大 Combo | 本局最高连击 | 整数 |
| 用时 | 从第一音到最后一音 | mm:ss |
| PERFECT | 数量 | 整数 |
| GREAT | 数量 | 整数 |
| GOOD | 数量 | 整数 |
| MISS | 数量 | 整数 |
| 综合分 | 可选，默认折叠 | 百分比 1 位小数 |

- 四类数量之和必须等于谱面音符数；不一致时不展示数字，改为“统计异常”。
- 准确率与判定数量使用同一套数据，避免矛盾。
- 跟弹模式显示“首按准确率”“最大 Combo”“跳过句数”。

### 4.4 新纪录规则

| 记录 | 判定 |
| --- | --- |
| 新分数纪录 | 本局分数 > 历史最高分（严格大于） |
| 新评级纪录 | 本局评级高于历史最佳评级 |
| 新准确率纪录 | 本局准确率 > 历史最高准确率 |
| 新 Combo 纪录 | 本局最大 Combo > 历史最高 Combo |

- 只展示最高的一个标识，优先级：新分数纪录 > 新评级纪录 > 新准确率 > 新 Combo。
- 首次完成不显示“新纪录”，显示“首次完成”。
- 跟弹模式以准确率作为主纪录。
- 平纪录不算新纪录。

### 4.5 最佳成绩存储

按“曲目 × 模式”分别保存：

| 字段 | 说明 |
| --- | --- |
| bestScore | 最高分 |
| bestGrade | 最佳评级（S 最高） |
| bestAccuracy | 最高准确率 |
| bestCombo | 最高 Combo |
| playCount | 游玩次数 |
| clearCount | 完成次数 |
| lastPlayedAt | 最近游玩时间 |
| bestRecordId | 对应的演奏记录（可选） |

- 每项独立取历史最优，不要求同一次达成。
- 评级比较顺序：S > A > B > C > D。
- 分数为 0 的跟弹模式不参与分数比较。
- 写入失败时保留本局数据在内存，提示“成绩保存失败，请重试”，提供重试按钮。

### 4.6 保存演奏记录

- 点击“保存演奏” → 弹出标题输入，默认“小星星 · 节奏挑战 · 10-30 21:40”。
- 标题 1～20 字，空值禁用保存。
- 保存内容：本局按键事件、音色、来源、曲目、成绩统计。
- 保存成功：按钮变为“已保存”，Toast“已保存到我的演奏”。
- 保存失败：Toast“保存失败，请检查存储空间”，保留输入内容。
- 保存后不可重复保存同一局；可去“我的演奏”重命名/删除。
- 若本局未产生任何有效按键，禁用保存。

### 4.7 下一首规则

- 按曲库排序（难度升序、同难度首发顺序）找下一首。
- 跳过未解锁曲目。
- 已是最后一首：按钮显示“回到曲库”，点击回曲库。
- 下一首进入曲目详情，不自动开始，避免误触。

### 4.8 再来一次

- 保持曲目、模式、音色、速度、严格度、校准。
- 重新加载谱面与背景（若已缓存则直接开始）。
- 不重置最佳成绩。
- 若本局记录未保存，弹出轻提示“本局演奏尚未保存，仍要重开吗？”，可取消。

### 4.9 成就与解锁提示

- 结算时检查 F11 的成就条件；解锁以 Toast 形式在结算页右上角出现，不遮挡评级。
- 不连续弹出超过 2 个；更多成就排队，结算页停留时逐个展示。
- 章节解锁（F08）以单独横幅展示，不混在成就里。

## 6. 界面与交互要求

- 结算页不可通过返回手势直接跳过保存提示；返回首页前若有未保存记录，轻提示一次。
- 评级与分数是视觉第一层；统计是第二层；操作是第三层。
- “再来一次”按钮尺寸 ≥360×96，位于右下拇指区。
- “返回首页”不与“再来一次”相邻，避免误触。
- 新纪录标识有金色描边与轻微呼吸，不使用全屏闪烁。
- 数字使用等宽字体，滚动时不左右跳动。
- 减少动效时，取消光效、粒子、滚动，直接显示最终数字。
- 结算页背景使用本局曲目背景的暗化版本，保持沉浸感。

## 11. 风险与待确认

| 风险 | 说明 | 应对 |
| --- | --- | --- |
| 结算信息过多 | 玩家不看统计 | 三层信息结构；统计可折叠 |
| 低评级挫败 | D 评级导致流失 | 中性文案；强调“再来一次” |
| 新纪录判定争议 | 分项纪录过多 | 只展示最高优先级一个 |
| 跟弹无分数 | 结算空 | 以首按准确率为主指标 |
| 保存失败 | 玩家丢失作品 | 保留内存数据 + 重试；提示存储空间 |
| 动画过长 | 重复游玩烦躁 | 可点击跳过；记忆跳过偏好（P1） |
