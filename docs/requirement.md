## 1. 游戏梗概

> **KeyTune · 键音 —— Play by Keys**
>
> KeyTune 是一款专为手机横屏设计的轻量音乐小游戏。玩家根据屏幕提示，在 15 键虚拟钢琴上按下对应琴键，跟随旋律完成演奏；系统用 PERFECT / GREAT / GOOD / MISS 判定每次按键，以 Combo、得分和评级给出即时反馈。你既可以跟着曲目挑战节奏，也可以自由弹奏、识别和弦，还能把整段演奏记录成可回放的作品。它不追求真实钢琴模拟，而是用「看得懂的音符 + 按得爽的琴键 + 停不下来的连击」，让任何人在 3 秒内上手、30 秒内完成第一段旋律。

### 1.1 一句话定位

> 一个 3 分钟就能玩起来、30 秒就能完成第一段旋律的横屏 H5 音乐小游戏。

### 1.2 核心体验闭环

```text
选曲 / 直接按键
      ↓
看清提示（下一个音 / 下落的音符）
      ↓
按下琴键，立即听到声音、看到反馈
      ↓
连续命中，Combo 增长，分数累积
      ↓
完成旋律，获得评级与成绩
      ↓
保存演奏记录 / 分享成绩
      ↓
再来一次，挑战更高评级
```

### 1.3 真正让游戏“好玩”的四件事

```text
🎵 音乐（旋律本身好听、音准正确）
      +
🎮 判定（按得准不准，有明确反馈）
      +
🔥 Combo（连续命中，有放大奖励）
      +
🎹 自己演奏（自由弹、可录制、可回放）
```

## 2. 产品定位与目标

### 2.1 产品定位

- 轻量音乐小游戏，不是钢琴教学软件，也不是专业编曲工具。
- 以手机横屏为主要形态，竖屏时引导旋转。
- 单局 30 秒～3 分钟，适合碎片时间。
- 无账号、无强制联网、打开即玩。
- 游戏与乐器二合一：既能闯关挑战，也能随手弹奏。

### 2.2 产品目标

| 目标 | 衡量方式 |
| --- | --- |
| 3 秒上手 | 首次进入的用户在无文字教程的情况下，3 秒内按下第一个琴键 |
| 30 秒成就感 | 首次用户在选择第一首曲目后 30 秒内完成一段可听见的旋律 |
| 核心循环成立 | 用户完成一首曲目后，愿意点击“再来一次”或进入下一首 |
| 演奏可留存 | 用户能把自由演奏或游戏过程保存为记录并回放 |
| 轻量可传播 | 首屏快速打开，成绩可生成分享卡片 |

### 2.3 非目标

- 不做真实钢琴的逐键采样与物理建模。
- 不做专业乐理课程、作业与考级体系。
- 不做多人在线合奏、实时对战。
- 不做用户上传曲谱、社区与内容审核（首版）。
- 不做依赖服务器的全球排行榜。
- 不做麦克风录音（首版；后续作为独立功能）。

### 2.4 设计原则

| 原则 | 具体要求 |
| --- | --- |
| 3 秒上手 | 无弹窗教程；首屏直接出现可按的琴键与“按 C”提示；按下即有声音和视觉反馈 |
| 30 秒成就感 | 第一首曲目不超过 16 个音，BPM ≤ 80，只使用 C/D/E 三个音 |
| 渐进复杂度 | 3 键 → 5 键 → 7 键 → 黑键 → 双音 → 三和弦 → 长音 → 滑奏，按关卡与曲目逐步引入 |
| 游戏与乐器二合一 | 任何页面都能快速进入自由演奏；自由演奏可一键录制 |
| 低依赖、轻量 | 音符优先实时合成，不依赖大体积音频；首屏资源可控 |
| 反馈即时 | 按键到发声、到高亮、到判定文字，均需在玩家感知的“同时”发生 |
| 尊重失误 | 新手模式不失败、不羞辱；错误有温和提示，可无限重试 |

## 3. 目标用户与使用场景

### 3.1 目标用户

| 用户类型 | 特征 | 核心诉求 |
| --- | --- | --- |
| 音乐小白 / 儿童（8～12 岁） | 不识谱，注意力短 | 看得懂、按得动、马上有声音 |
| 碎片时间玩家 | 每次 1～5 分钟 | 快速开局、单局短、随时退出 |
| 轻度音乐爱好者 | 听过这些曲子，愿意挑战 | 节奏判定、Combo、评级、刷分 |
| 表达型用户 | 喜欢记录与分享 | 自由弹奏、录制回放、成绩卡片 |

### 3.2 典型场景

- 课间 / 通勤：单手横握，玩一首 30 秒的曲子。
- 家庭场景：家长与儿童轮流挑战同一首曲目。
- 休息时：不选曲，直接自由弹奏，录一段旋律。
- 社交分享：把 S 评级成绩生成卡片，发给朋友。
- 离线场景：飞机、地铁无网络时仍可完整游玩。

### 3.3 设备与姿态

- 主要设备：5.5～7.0 英寸手机，横屏，双手拇指操作。
- 次要设备：平板、桌面浏览器（鼠标点击 / 键盘按键，基础可用即可）。
- 支持 16:9、18:9、19.5:9、20:9、21:9 等比例；需适配刘海、挖孔、圆角与底部手势区。
- 竖屏时显示“请旋转设备”的插画与文字，不进入游戏。

## 5. 术语表

| 术语 | 定义 |
| --- | --- |
| 键位 | 15 个可按的虚拟琴键，10 白 + 5 黑 |
| 音符事件 | 一次“按下”或“松开”，包含音名、时间、力度等 |
| 谱面 | 一首曲目的全部目标音符及时值 |
| 判定 | 将玩家按键时间与目标音符时间比较，得出 PERFECT / GREAT / GOOD / MISS |
| Combo | 连续命中数；MISS 或断连条件触发后归零 |
| 准确率 | 按判定权重折算的命中比例 |
| 综合分 | 由准确率、Perfect 率、Combo、节奏误差合成的评级依据 |
| 演奏记录 | 以事件序列保存的演奏，可回放，不是音频文件 |
| 跟弹 | 系统先示范一句，玩家再重复 |
| 节奏挑战 | 音符下落，玩家在判定线处按键 |
| 闯关 | 按章节与关卡组织曲目，逐关解锁 |
| 自由演奏 | 无任务，任意按键发声，可识别和弦、可录制 |
| 聚焦模式 | 仅高亮当前曲目用到的键，其余键降低存在感 |


### 6.3 全局导航

- 首页为唯一一级入口；二级页面统一左上角返回。
- 游戏内不显示主导航，仅保留暂停按钮。
- 从游戏退出必须二次确认，避免误触丢失成绩。
- 任何页面在 3 次点击内可到达“自由演奏”。

## 7. 业务流程设计

### 7.1 首次进入与 3 秒上手

```text
打开应用
  ↓
加载（≤2.5 秒，显示 Logo 与进度）
  ↓
检测屏幕方向
  ├── 竖屏 → 显示“请横屏”插画，旋转后继续
  └── 横屏 → 进入首页
        ↓
首页中央直接显示 15 键键盘 + 呼吸提示“按 C”
        ↓
用户按下 C
        ↓
立即发声 + 键帽高亮 + 音符名“C”浮起
        ↓
解锁成就“第一个音”
        ↓
提示切换为“按 C 开始第一首”，引导进入 S01
```

要点：

- 不出现全屏教程、不要求授权、不要求登录。
- 首次按下任意键都应有反馈；提示只强调 C，不限制其他键。
- 即使用户不点“开始”，也能在首页键盘上随意发声。

### 7.2 核心游戏循环

```text
选择曲目 / 模式
  ↓
准备页（可选音色、速度、严格度）
  ↓
3-2-1 倒计时
  ↓
演奏
  ├── 命中 → 判定文字 + 音效 + Combo + 分数
  ├── 漏音 → MISS + Combo 归零
  └── 暂停 → 暂停页 → 继续（重新倒计时）或退出
  ↓
曲目结束
  ↓
结算（评级、分数、统计、是否新纪录）
  ↓
保存成绩 / 保存演奏记录 / 分享
  ↓
再来一次 / 下一首 / 返回首页
```

### 7.3 跟弹模式流程

```text
选择曲目
  ↓
整曲预览（可选，3 秒）
  ↓
第 1 乐句示范：高亮琴键 + 播放旋律
  ↓
提示“轮到你”
  ↓
玩家逐个按键
  ├── 按对 → 前进到下一个音，播放该音
  ├── 按错 → 温和错误提示，琴键抖动，不前进，允许重试
  └── 停顿超过 5 秒 → 再次高亮目标键并播放提示音
  ↓
乐句完成 → “很好！”反馈 → 下一乐句示范
  ↓
全部乐句完成 → 结算
```

规则：

- 默认不限制节拍，按对即前进；可在设置中开启“严格节拍”。
- 每个音只记录第一次按键结果用于准确率；重试不重复计分。
- 不设失败；可无限重试，可随时“再听一次”。
- 错误按键不扣 Combo（新手保护），但会计入准确率。

### 7.4 节奏挑战流程

```text
选择曲目
  ↓
准备页：音色、下落速度（慢/标准/快）、严格度
  ↓
倒计时 3-2-1（可听节拍）
  ↓
音符按下落时间从上方进入，与对应琴键同列
  ↓
到达判定线时按键
  ├── 时间差在窗口内且音高正确 → PERFECT / GREAT / GOOD
  ├── 音高错误或超时 → MISS
  └── 额外空击 → 不扣分、不断 Combo（标准模式）
  ↓
曲目结束 → 结算
```

规则：

- 不设生命值，MISS 不会中止曲目。
- 长音、滑奏在 P1 引入；首版只做单音与和弦（和弦作为同一时刻的多个音）。
- 暂停时音符冻结、声音淡出；继续时 3 秒倒计时。
- 切后台自动暂停；回到前台不自动继续，需玩家确认。

### 7.5 闯关模式流程（P1）

```text
首页 → 闯关地图
  ↓
选择章节（第一章默认解锁）
  ↓
选择关卡
  ├── 未解锁 → 提示解锁条件
  └── 已解锁 → 关卡详情 → 开始
  ↓
完成关卡 → 星级结算
  ├── 完成（任意评级）→ 1 星
  ├── B 及以上 → 2 星
  └── A 及以上 → 3 星
  ↓
获得 ≥1 星 → 解锁下一关
  ↓
章节全部通关 → 章节奖励与下一章
```

### 7.6 自由演奏与录制流程

```text
进入自由演奏
  ↓
按键即发声，支持多键同时按
  ↓
同时按住 2～4 个音 → 显示和弦名称
  ↓
点击“录制”
  ↓
3-2-1 倒数（可关闭）→ 开始记录按键事件
  ↓
演奏中可切换音色、开关节拍器
  ↓
点击“停止” → 试听 → 保存 / 重录 / 丢弃
  ↓
保存后出现在“我的演奏”
```

规则：

- 录制只记录演奏事件，不采集麦克风、不生成音频文件。
- 单条记录最长 5 分钟；超过自动停止并提示保存。
- 录制中退出需确认，可选择保存草稿或丢弃。
- 回放严格按原始时间触发声音与琴键高亮。

### 7.7 结算与分享流程

```text

  ↓

  ↓

```

### 7.8 每日挑战流程（P2）

```text
每日 00:00（本地时间）刷新
  ↓
从已解锁曲库中按日期确定 1 首“今日曲目”
  ↓
首页展示今日曲目、今日最佳、连续参与天数
  ↓
开始挑战（可多次，取当日最高分）
  ↓
结算 → 更新今日最佳 → 可分享
```

- 完全离线，无全球排行；“最佳”仅指本机。
- 同一设备同一天结果稳定，不随刷新改变。

### 7.9 暂停、中断与恢复

| 场景 | 行为 |
| --- | --- |
| 点击暂停 | 立即暂停计时与音符，声音 200ms 内淡出 |
| 切后台 / 锁屏 | 自动暂停，停止发声 |

| 游戏内退出 | 二次确认；未结束的成绩不保存 |

| 页面刷新 / 崩溃 | 已保存的成绩与记录不丢失；进行中的一局不恢复 |

### 7.10 数据与重置流程

```text
设置 → 数据管理
  ├── 查看本地数据占用
  ├── 清除演奏记录（二次确认）
  ├── 清除成绩与成就（二次确认）
  └── 清除全部数据（输入/长按确认）
```

- 清除后不可恢复，必须明确告知。
- 清除全部数据后回到首次进入状态（保留应用本身）。

## 9. 规则与数值

### 9.1 键位与音高

| 类型 | 键位（左→右） | 音高范围 |
| --- | --- | --- |
| 白键（10） | C4 D4 E4 F4 G4 A4 B4 C5 D5 E5 | C4～E5 |
| 黑键（5） | C#4 D#4 F#4 G#4 A#4 | C#4～A#4 |

黑键位置：C-D 之间、D-E 之间、F-G 之间、G-A 之间、A-B 之间；E-F 与 B-C 之间无黑键。

标准音高（A4=440Hz）参考：C4 261.63、D4 293.66、E4 329.63、F4 349.23、G4 392.00、A4 440.00、B4 493.88、C5 523.25、D5 587.33、E5 659.25。

为什么是 15 键：

- 8 键太简单，音乐表现力不足；12 键缺少黑键或第二八度，稍复杂的旋律不够用。
- 15 键 = 完整一个八度（7 白 + 5 黑）+ 第二八度的 C/D/E，覆盖 C4～E5，能弹儿歌、简单流行与三和弦。
- 手机横屏下，10 个白键仍能保证每个键有足够宽度，不至于误触；黑键只保留第一八度，避免过度拥挤。
- 这是 MVP 的取舍，不是永久上限；后续可在不改变交互模型的前提下扩展音域。

### 9.2 难度体系

难度由 7 个维度共同决定，不只加速度：

| 维度 | 低难度 | 高难度 |
| --- | --- | --- |
| 音符数量 | ≤16 | ≥80 |
| 速度（BPM） | ≤80 | ≥160 |
| 音域 | 3 键 | 15 键 |
| 黑键 | 无 | 大量 |
| 同时按键 | 单音 | 三音和弦 |
| 长音 | 无 | 多处长音 |
| 滑奏 | 无 | 连续滑奏 |

| 等级 | 能力要求 | 典型内容 |
| --- | --- | --- |
| Lv1 | C D E 单音 | 3 键练习曲 |
| Lv2 | C～G 单音 | 小星星、两只老虎 |
| Lv3 | 完整七声音阶 | 欢乐颂、生日快乐 |
| Lv4 | 加入 5 个黑键 | 黑键练习 |
| Lv5 | 快速连续音符 | 120～160 BPM |
| Lv6 | 长音 | 按住与释放 |
| Lv7 | 双音 | C+E |
| Lv8 | 三音和弦 | C+E+G |
| Lv9 | 滑奏 | 快速刮奏 |
| Lv10 | 完整歌曲 | 综合运用 |

曲目难度取各维度所需等级的最大值；UI 展示 1～10 的整数。

### 9.3 节奏判定

基准窗口（标准严格度）：

| 判定 | 时间差 | 基础分 | 准确率权重 |
| --- | --- | --- | --- |
| PERFECT | 0～±80ms | 100 | 100% |
| GREAT | ±81～±160ms | 70 | 80% |
| GOOD | ±161～±300ms | 40 | 50% |
| MISS | >±300ms，或未在窗口内按键 | 0 | 0% |

修正规则：

- 严格度：宽松 ×1.3，标准 ×1.0，严格 ×0.75。
- BPM 修正：BPM ≥140 时 ×0.9；BPM ≤80 时 ×1.15。
- 结果四舍五入到 5ms，最大不超过 500ms。
- 判定以“按下”时刻为准；长音以“按下”与“松开”共同判定（P1）。
- 和弦：所有目标音在 120ms 内按齐才视为一次命中；缺音记 MISS；多按的音不参与该和弦判定。
- 空击：标准模式不扣分、不断 Combo；严格模式断 Combo（P1）。

### 9.4 得分与 Combo

单音得分：

```text
单音得分 = 基础分 × 当前 Combo 倍率
最终得分 = 所有单音得分之和（四舍五入取整）
```

Combo 倍率：

| 当前 Combo | 倍率 |
| --- | --- |
| 1～9 | ×1.0 |
| 10～19 | ×1.2 |
| 20～49 | ×1.5 |
| 50+ | ×2.0 |

- 命中后 Combo 先 +1，再按新 Combo 取倍率。
- MISS 后 Combo 归零；下一次命中从 1 开始。
- 跟弹模式采用简化计分：只统计准确率与最大 Combo，不显示倍率放大（避免新手困惑）；结算仍给评级。

### 9.5 准确率与评级

```text
准确率 = Σ(每个音符的准确率权重) / 谱面音符总数
Perfect 率 = PERFECT 数 / 谱面音符总数
Combo 率 = 最大 Combo / 谱面音符总数（上限 1）
节奏误差分 = 1 - 平均绝对误差 / 300ms（下限 0）
综合分 = 0.55×准确率 + 0.20×Perfect 率 + 0.15×Combo 率 + 0.10×节奏误差分
```

评级：

| 评级 | 综合分 | 附加条件 |
| --- | --- | --- |
| S | ≥95% | 准确率 ≥98% 且 MISS ≤1 |
| A | ≥90% | 准确率 ≥90% |
| B | ≥80% | — |
| C | ≥60% | — |
| D | <60% | — |

- 不满足附加条件时降一级。
- 跟弹模式无“节奏误差”时，将该项按准确率计入。
- 结算页展示综合分（可选）与评级；默认只展示评级，避免信息过载。

### 9.6 闯关星级与解锁

| 星级 | 条件 |
| --- | --- |
| 1 星 | 完成关卡（到达结算） |
| 2 星 | 评级 B 及以上 |
| 3 星 | 评级 A 及以上 |

- 获得 ≥1 星解锁下一关。
- 已获得星级取历史最高，不因低分下降。
- 章节通关条件：该章全部关卡 ≥1 星。

### 9.7 和弦识别

支持范围（根音 + 性质）：

| 性质 | 音程结构（相对根音） | 英文 | 中文 |
| --- | --- | --- | --- |
| 大三 | 0, 4, 7 | Major | 大三和弦 |
| 小三 | 0, 3, 7 | Minor | 小三和弦 |
| 减三 | 0, 3, 6 | Diminished | 减三和弦 |
| 增三 | 0, 4, 8 | Augmented | 增三和弦 |
| 挂二 | 0, 2, 7 | Sus2 | 挂二和弦 |
| 挂四 | 0, 5, 7 | Sus4 | 挂四和弦 |

规则：

- 2～4 个音在 80ms 内同时按下才识别；琶音不识别。
- 优先匹配原位与转位；转位显示“C Major / C 大三和弦（第一转位）”。
- 无法匹配时显示“—”。
- 黑键根音同样支持，如 C# Major。

### 9.8 音色与音量

| 音色 | 听感目标 | 适用 |
| --- | --- | --- |
| Piano | 柔和、有起音、自然衰减 | 默认，跟弹与挑战 |
| Bell | 明亮、泛音丰富、尾巴较长 | 小星星、儿歌 |
| Synth | 电子、短促、游戏感 | 节奏挑战、自由演奏 |

音量：

- 总音量 = 音乐音量 × 效果音量 × 主音量（0～100 映射为感知音量，非线性）。
- 默认：主 80、音乐 70、效果 80。
- 静音时所有声音为 0，但视觉反馈保留。
- 切换音色/音量不得产生爆音、咔哒声。

### 9.9 成就定义

| 编号 | 名称 | 解锁条件 | 类型 |
| --- | --- | --- | --- |
| A01 | 第一个音 | 第一次按下任意琴键并发声 | 一次性 |
| A02 | 初学者 | 完成第一首曲目（任意模式） | 一次性 |
| A03 | 连击达人 | 单局达到 50 Combo | 一次性 |
| A04 | 八度大师 | 累计按下全部 10 个白键 | 累计 |
| A05 | 黑键入门 | 第一次按下任意黑键 | 一次性 |
| A06 | 和弦大师 | 第一次成功识别三和弦 | 一次性 |
| A07 | 完美演奏 | 一首曲目准确率 100%（全部 PERFECT） | 一次性 |
| A08 | 我的作品 | 保存第一条演奏记录 | 一次性 |
| A09 | 演奏家 | 完成 10 首不同曲目 | 累计 |
| A10 | 钢琴大师 | 全部曲目达到 S 评级 | 终局 |

### 9.10 每日挑战规则

- 以本地日期（YYYY-MM-DD）为种子，从已解锁曲库中确定 1 首。
- 同一天内多次进入结果一致；跨天自动刷新。
- 可无限次挑战，只保留当日最高分与最高评级。
- 连续参与天数：当日完成至少 1 次完整挑战则 +1；中断则归 1。
- 无服务器、无全球排名。

## 10. 内容与数据需求

### 10.1 曲谱内容模型（概念）

一首曲目至少包含：

| 字段 | 说明 | 约束 |
| --- | --- | --- |
| id | 唯一标识 | 小写字母、数字、连字符 |
| title | 中文名 | 1～20 字 |
| titleEn | 英文名 | 可选 |
| difficulty | 难度 | 1～10 整数 |
| bpm | 速度 | 40～220 |
| timeSignature | 拍号 | 默认 4/4 |
| duration | 时长 | 10～300 秒 |
| notes | 音符列表 | 至少 1 个 |
| notes[].notes | 同时发声的音名 | 1～3 个，如 ["C4","E4","G4"] |
| notes[].time | 相对开始时间 | 0～300000ms |
| notes[].duration | 持续时间 | 50～10000ms |
| notes[].velocity | 力度 | 0.1～1.0，可选 |
| category | 分类 | 入门/初级/中级/和弦 |
| cover | 封面标识 | 必填 |
| unlock | 解锁条件 | 可选 |
| tags | 标签 | 可选 |

要求：

- 曲谱与程序分离，新增曲目不需要改玩法逻辑。
- 同一曲目可被跟弹与节奏挑战复用。
- 谱面时间以毫秒为单位，允许 ±1ms 精度。
- 曲目结束时间 = 最后一个音符 time + duration + 2 秒余量。

### 10.2 演奏记录模型（概念）

| 字段 | 说明 |
| --- | --- |
| id | 唯一标识 |
| title | 用户可编辑标题 |
| createdAt | 创建时间 |
| duration | 总时长（ms） |
| timbre | 录制时音色 |
| source | 自由演奏 / 跟弹 / 节奏挑战 |
| songId | 来源曲目，自由演奏为空 |
| events | 事件数组 |
| events[].note | 音名，如 C4 |
| events[].type | down / up |
| events[].time | 相对开始时间（ms） |
| events[].velocity | 力度，可选 |
| stats | 来源为游戏时的分数、准确率、Combo |

约束：

- 单条 ≤5 分钟；最多 20 条；超出时提示删除最旧记录。
- 事件按时间升序保存；同一时刻允许多个 down（和弦）。
- 保存前校验：至少有 1 个 down 事件。
- 记录损坏时跳过该条并提示，不影响其他记录。

### 10.3 本地档案内容

| 数据 | 说明 |
| --- | --- |
| 设置 | 音量、音色、严格度、校准、震动、动效、语言 |
| 曲目成绩 | 每曲每模式的最佳分数、评级、Combo、准确率、游玩次数 |
| 闯关进度 | 每关星级、解锁状态、章节奖励 |
| 成就 | 解锁状态、解锁时间、进度 |
| 演奏记录 | 记录列表与事件 |
| 每日挑战 | 当日曲目、当日最佳、连续天数、最后参与日期 |
| 新手状态 | 是否已按下第一个音、是否完成首曲 |

### 10.4 内容文案要求

- 所有面向玩家的文案使用简体中文，语气轻松、短句、无术语堆砌。
- 判定文字使用英文大写：PERFECT / GREAT / GOOD / MISS。
- 和弦名称中英并列；音名使用国际记法（C4、C#4）。
- 错误提示不使用责备性词汇，例如用“再试一次”而非“你错了”。
- 文案与图片分离，图片内不烘焙文字（Logo 除外）。

## 11. 非功能与性能要求

### 11.1 性能指标

测试条件：近 3 年中端手机（如 2022～2024 年主流安卓中端机、iPhone 11 及以上），横屏，亮度 50%，音量 60%，常温。

| 编号 | 指标 | 要求 |
| --- | --- | --- |
| NFR-01 | 冷启动到首页可交互 | ≤2.5 秒（4G，首次）；≤1.5 秒（缓存后） |
| NFR-02 | 首页进入游戏 | ≤800ms（已加载资源）；曲目切换 ≤500ms |
| NFR-03 | 触感到发声 | ≤50ms（P95）；≤80ms（P99） |
| NFR-04 | 触感到视觉反馈 | ≤1 帧（16.7ms） |
| NFR-05 | 游戏帧率 | 60fps 为目标；95% 帧 ≥45fps；无 >100ms 卡顿帧 |
| NFR-06 | 判定时间精度 | 与目标时间偏差 ≤±15ms；3 分钟内时钟漂移 ≤10ms |
| NFR-07 | 多指 | 至少 10 点触控；5 音同按无丢音、无卡键 |
| NFR-08 | 内存 | 峰值 ≤200MB；连续 3 首后增长 ≤10MB |
| NFR-09 | 资源体积 | 首屏 ≤1.5MB；完整初始包 ≤3MB；单曲新增 ≤1.5MB |
| NFR-10 | 连续游玩 | 30 分钟耗电 ≤10%；机身表面温度 ≤40℃ |
| NFR-11 | 离线 | 首次加载后，所有核心模式可离线完整游玩 |
| NFR-12 | 存档可靠性 | 保存成功率 ≥99.9%；崩溃后已保存数据不丢失 |
| NFR-13 | 稳定性 | 无崩溃会话 ≥99.5%；无“卡死需刷新” |
| NFR-14 | 音频质量 | 无削波、无爆音；峰值 ≤-1dBTP；切后台 200ms 内静音 |

### 11.2 兼容性

| 项目 | 要求 |
| --- | --- |
| 系统 | iOS 15+；Android 10+ |
| 浏览器 | Safari、Chrome、Edge 最新两个大版本；微信内置浏览器、主流安卓 WebView |
| 屏幕 | 16:9～21:9；分辨率 1280×720～2340×1080；5.5～7.0 英寸为主 |
| 异形屏 | 刘海、挖孔、圆角、底部手势区安全适配 |
| 方向 | 仅横屏；竖屏显示旋转提示 |
| 桌面 | 鼠标与键盘可完成核心流程；不做专门桌面布局 |
| 输入 | 触摸优先；支持鼠标；支持键盘映射（P1） |

### 11.3 可靠性与数据

- 所有成绩、设置、记录在本机持久保存；刷新、杀进程后不丢失已保存内容。
- 写入失败时给出明确提示，不静默失败。
- 单条记录损坏不影响其他记录；档案损坏时降级为默认设置并提示。
- 不因网络断开影响任何核心玩法。
- 清除数据必须二次确认，且提示不可恢复。

### 11.4 可用性与无障碍

- 主要按钮可点击区域 ≥44×44 CSS px；琴键远大于该值。
- 文字与背景对比度 ≥4.5:1；判定文字有形状/颜色双重区分，不只靠颜色。
- 支持“减少动效”：关闭粒子、屏幕震动、评级翻转等强动效。
- 支持关闭震动；震动仅用于 Combo 里程碑、错误提示、结算，不连续震动。
- 所有图标按钮有可读的无障碍名称。
- 音名标签清晰；色弱模式下白键/黑键仍有明度差。
- 不依赖长按、双击、拖拽完成核心操作；所有核心操作单击可达。

### 11.5 隐私与安全

- 无账号、无登录、无手机号、无通讯录权限。
- 不申请麦克风、相机、定位权限（麦克风录音为 P2 独立功能，需单独授权与说明）。
- 不上传演奏记录、成绩、设备信息。
- 分享卡片不包含设备标识、位置、真实姓名。
- 提供“清除全部数据”入口。
- 隐私说明使用玩家能理解的语言，不使用法律黑话堆砌。

### 11.6 本地化

- 首发简体中文；文案与图片分离，为英文预留。
- 数字使用千分位（2,380）；时间使用 mm:ss。
- 日期使用本地时区；每日挑战按本地 00:00 刷新。
- 音名、和弦名、判定词不翻译。

## 12. 素材总体规范

## 13. 验收与发布标准

### 13.1 MVP 验收清单

- [ ] 横屏进入首页 ≤2.5 秒，竖屏有旋转提示。
- [ ] 15 键音高正确，黑键位置正确，5 指同按不丢音。
- [ ] 触感到发声 P95 ≤50ms，视觉反馈 ≤1 帧。
- [ ] 三种音色可切换，音量可调并记忆。
- [ ] 12 首曲目可完整游玩，曲谱与程序分离。
- [ ] 跟弹模式可示范、等待、纠错、完成、结算。
- [ ] 节奏挑战有下落音符、判定线、四类判定、Combo、分数、进度。
- [ ] 判定窗口、得分、评级可按第 9 章复算。
- [ ] 结算展示评级、分数、准确率、最大 Combo、判定统计、新纪录。
- [ ] 自由演奏支持和弦识别，C/E/G 显示 C Major / C 大三和弦。
- [ ] 可录制、保存、回放、重命名、删除演奏记录。
- [ ] 成绩、设置、记录刷新后不丢失。
- [ ] 切后台自动暂停并静音，回前台需确认继续。
- [ ] 核心玩法离线可用，无账号、无网络请求依赖。
- [ ] 30 分钟连续游玩无崩溃、无明显发热与内存增长。

### 13.2 体验验收

- 首次用户 3 秒内按下第一个键；无需文字教程。
- 首次用户 30 秒内完成 S01 的第一句（不少于 4 个音）。
- 5 名首次用户中至少 4 名能独立完成一首曲目并看到结算。
- 结算页“再来一次”点击率作为后续观察指标，不作为首版硬门槛。
- 错误提示不引起挫败；新手连续按错 3 次仍愿意继续。

### 13.3 发布门槛

- 兼容性矩阵全部通过：iOS Safari、Android Chrome、微信内置浏览器各至少 2 台真机。
- 无 P0/P1 级缺陷；P2 缺陷有明确排期。
- 性能指标在目标机型达标。
- 素材版权与响度检查完成。
- 隐私说明、数据清除、版本号可访问。

## 14. 风险与待确认

| 编号 | 风险/问题 | 影响 | 当前默认决策 |
| --- | --- | --- | --- |
| R01 | 安卓/微信 WebView 音频延迟差异大 | 判定不准、手感差 | 提供音画校准；判定以音频时钟为准；目标 P95 ≤50ms |
| R02 | 多指触控在部分机型存在“断触” | 和弦丢音 | 至少 5 指测试；和弦判定允许 120ms 内按齐 |
| R03 | 15 键在小屏上过窄 | 误触 | 最小键宽 56 CSS px；窄屏降低黑键宽度但不小于 40px |
| R04 | 曲目版权 | 无法上线 | 仅使用公有领域旋律或原创编配；编曲与录音需授权 |
| R05 | iOS 无法强制横屏 | 体验中断 | 竖屏插画引导；旋转后恢复；不依赖强制锁定 |
| R06 | 本地数据被清理 | 成绩丢失 | 明确提示；P1 提供导出/导入；不做云端承诺 |
| R07 | 评级公式主观 | 争议 | 首版按第 9.5 节执行；上线后根据分布调整 |
| R08 | 新手觉得“跟弹”太慢 | 流失 | 提供跳过本句、整曲预览；严格模式 P1 |
| R09 | 自由演奏和弦识别误报 | 玩具属性受损 | 80ms 同时按下才识别；无法匹配显示“—”；不猜测 |

### 待确认问题（需产品评审拍板）

1. 是否保留全部 12 首曲目免费，还是按闯关进度解锁？默认：快速游玩全部开放，闯关模式单独设解锁。

7. 长音与滑奏是否进入首发？默认：P1，首发只做单音与三和弦。
8. 录音是否包含麦克风？默认：不包含；演奏记录与音频录音在产品命名上严格区分。
